## Minor-Version Upgrade Procedures (Safe, Auditable & Idempotent)

Before any upgrade, back up Celina's state independently of OS snapshots:
```bash
celina-export ~/celina-pre-upgrade.tar.gz
./install.sh --dry-run --upgrade    # apt --simulate style diff (0 disk writes)
```

### Upgrading from `v4.3` → `v4.4`
1. **Preview the Exact Diff (Zero Writes):**
   - Run `./install.sh --dry-run --upgrade` to inspect:
     - `celina migrate --dry-run` (schema `4.3 -> 4.4`, newly registered tools, and promotion of all 7 `files_office` mutation tools to Tier-2 approval),
     - Pinned GNOME extension versions in `system/gnome/extensions.lock` vs. currently installed versions,
     - OS config drop-ins (`NEW` / `MODIFIED` / `unchanged`).
2. **Apply In-Place:**
   - Run `./install.sh --upgrade` (or `./install.sh --profile default-8gb`).
   - **SQLite Schemas:** `memory.db`, `cache.db`, and `spotlight_index.db` run non-destructive `CREATE TABLE IF NOT EXISTS` / `ALTER TABLE` migrations automatically via `celina migrate` (enabling WAL + `busy_timeout=5000`, `doc_chunks`, `float16` embeddings, and `lang_prefix`) without wiping memories, KG triples, or goals.
   - **Celina Tools & Tiers:** `celina migrate` merges new v4.4 tools/domains into `~/.config/celina/neural-schema.json`, enforces fail-closed Tier-2 precedence (removing promoted tools from `tier1_auto_tools`), and preserves custom persona names, nicknames, secrets (`~/.config/celina/env`), IoT allowlists, and trusted/quarantined skills.
   - **GNOME Extensions:** `install_ext()` replaces unpinned copies of the 8 managed extensions with the exact GNOME 48/49/50 pinned `version_tag` in `system/gnome/extensions.lock`; unrelated user-installed GNOME extensions coexist untouched.
3. **Post-Upgrade Verification:**
   ```bash
   ./install.sh --doctor
   ./install.sh --locale
   ./install.sh --verify
   ```

### Upgrading from `v4.2` → `v4.3` (or `v4.2` → `v4.4` Direct)
1. **State Backup:** Run `celina-export` (if v4.4 tools are present) or archive `~/.local/share/celina` and `~/.config/celina`.
2. **Legacy JSON Graph Migration:** Existing `semantic_memory.json` files from v4.2 are preserved alongside the upgraded SQLite `memory.db` (FTS5 + Ebbinghaus temporal decay + KG).
3. **Direct Jump Supported:** You do not need to install v4.3 first—running `./install.sh --upgrade` from v4.2 jumps directly to v4.4 and migrates `neural-schema.json` + all 3 SQLite DBs in one idempotent pass.
